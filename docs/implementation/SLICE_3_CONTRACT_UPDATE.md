# Slice 3 contract update

**Status:** five human MVP product decisions approved and reconciled in documentation only. This is not Slice 3 implementation approval; no application code, schema, migration, or final endpoint payload is created here. [SLICE_3_APPROVAL_DECISIONS.md](SLICE_3_APPROVAL_DECISIONS.md) and [SLICE_3_READINESS_REVIEW.md](SLICE_3_READINESS_REVIEW.md) remain historical pre-approval rationale.

## Approved decisions

1. **Gate timing:** a persistent authorized Event–Gate association is required before Organizer-only Draft → Published and independently rechecked before Organizer-only Published → Live. Partial Drafts remain savable; no new lifecycle state exists.
2. **Event Admin allowlist and management reads:** an assigned Admin's Slice 3 ordinary Draft/Published detail edits are only name, description, public venue/location, image/banner, and public category/tags; assigned-event gate configuration is separate. Capacity, visibility, schedule/time zone, registration times/cutoff, attendance/certificate policy, ownership, and lifecycle remain outside that allowlist. No generic Admin or unrestricted Live detail PATCH. Owned/assigned lists and scoped management details carry lifecycle, schedule/time-zone context, configuration, gates, readiness blockers, availability reasons, permitted actions, and revision as appropriate; public detail is a separate allowlisted read.
3. **PRIVATE entry:** a valid server-verifiable controlled link is both discovery route and bearer authority for allowlisted PRIVATE Published detail. Organizer controls issuance/distribution. Link possession needs neither account login nor guest OTP merely to view; registration ownership later requires verified account/guest proof. A guessed ID is insufficient. The link authorizes detail only while the server recognizes it for the associated PRIVATE event, it has not been invalidated, and the event remains Published. Invalidation or leaving Published ends access immediately. Invalid/invalidated/mismatched proof, non-Published event, and unknown/unauthorized private access have the same privacy-safe unavailable outcome. No recipient-bound invitation or rotation UI is in Slice 3.
4. **Registration availability:** event lifecycle, policy availability, and the one `REGISTERED` registration cap are distinct. Slice 3 may report Published policy reasons `NOT_OPEN_YET`, `OPEN`, `SCHEDULED_CLOSE_REACHED`, and `MANUALLY_CLOSED`, with multiple applicable blockers. It has no Registration records and cannot assert registered/remaining counts, capacity usage, or `CAPACITY_REACHED`. `OPEN` is not a working registration action. Public catalog/detail is Published-only; management views may explain Live/Completed/Cancelled closure, while known PRIVATE links to non-Published events are safely unavailable.
5. **Configured Gate:** authorized creation of a persistent Gate associated with its Event suffices for the transition guard. Staff assignment, device/scanner hardware, connectivity, scanner health, and operational readiness are later concerns, not Slice 3 prerequisites.

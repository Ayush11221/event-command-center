# Phase 2 Architecture Handoff: Vertical-Slice Implementation Sequence

**Status:** proposed execution order **after** approval of this documentation phase. This refines the implementation sequencing in [ROADMAP.md](ROADMAP.md); it does not start implementation or change Phase 1 scope. Each slice includes its failure/negative path, audit and observability hook, and relevant traceability IDs before it is accepted.

| Order / slice | Prerequisite | Deliverable | Tests and acceptance condition |
| --- | --- | --- | --- |
| 1. Runnable repository/tooling | Approved Phase 2 contracts | Minimal React/Vite, Express, FastAPI workspaces only when used; config validation, CI static checks, health; Compose database as needed. | Clean setup from instructions; services health-check, no business feature claim or secrets. |
| 2. Persistence + identity/RBAC foundation | 1; session/OTP and identity/locking decisions | Reviewed Prisma migrations for event/identity/assignment/audit core, account/guest proof and central action/resource authorization. | Disposable PostgreSQL migration, cross-event/owner/gate denial, OTP abuse/replay, audited grants. |
| 3. Organizer event lifecycle + discovery | 2 | Draft/configure/publish/Live/complete/cancel, PUBLIC allowlist and PRIVATE controlled entry, registration availability reasons. | Organizer-only transitions incl Live cancel, Admin cannot cancel; Cancelled blocks creation/check-in but retains rows; public leak tests. |
| 4. Registration + credential | 3; atomic capacity/identity design | Verified account/guest registration, default/future opening and closure causes, pre-check-in cancellation/re-registration, opaque QR. | Last-slot concurrency, duplicate user/guest email-or-phone, cutoff/OTP, capacity-only reopen, old token invalid, no contact in QR. |
| 5. Assigned gate + attendance/occupancy | 4; scan transaction/replay design | Gate scanner API/UI, `scan_id`, check-in, optional checkout/re-entry, append-only correction, rebuildable INSIDE projection. | Concurrent/retry/duplicate/wrong-event/CANCELLED tests; failed scan no count, cap-full not gate block, correction actor/reason and reconciliation; measure scan p95 under defined workload. |
| 6. Snapshot + live command center | 5; revision/publication mechanism | Event-scoped authoritative snapshot, Socket.IO updates, reconnect reconciliation and stale UX. | Role/gate isolation, loss/reorder/reconnect, optional transport failure cannot lose attendance; measured p95 under defined workload. |
| 7. Alerts | 6; condition evidence/staleness rules | Three deduplicated in-product alert categories and ACTIVE/ACKNOWLEDGED/RESOLVED actions. | INSIDE-based 90/100, no registration-full alert, no duplicate persistent alert, gate read-only/Volunteer none. |
| 8. Advisory forecast | 6; representative time series | FastAPI contract, baseline, fixed 30/60 estimates, uncertainty/freshness/unavailable UI. | Chronological baseline/metrics report and stale/timeout handling; no gate-policy mutation. Production threshold decided from evidence, not assumed. |
| 9. Certificate eligibility + explicit single issue | 5; artifact protection/provider choice | First check-in ELIGIBLE, built-in preview, explicit unique-ID issue/revoke, own artifact. | Eligibility alone generates/sends nothing, issue idempotent, access isolated, revoke audited. |
| 10. Batch issue + email delivery | 9; durable worker and sender/provider decision | DB-derived eligible batch, progress, independent asynchronous delivery and retry. | Partial/crash/concurrent recovery, ISSUED + FAILED, no duplicate logical artifact/send, recipient isolation; provider-unknown risk resolved. |
| 11. Bounded volunteer + completed results/audit | 2 and relevant event/attendance/certificate facts | Own assignment status, scoped results and restricted event audit search. | Own-task-only transitions, no general alert/admin access; results reconcile, audit reads authorized and audited. |
| 12. Cross-cutting hardening/release evidence | All relevant slices | Load/failure/security/a11y/backup-restore evidence, telemetry, deployment and demonstration docs. | Agreed workload and RPO/RTO targets measured, Must requirements traced, critical/high security findings resolved or explicitly owned; no unsupported production claims. |

The sequence is dependency-oriented, not a promise that later quality work waits until slice 12. Authentication, RBAC, audit, accessibility, tests and telemetry are part of each slice. Slice 9 can run alongside 6–8 once attendance is stable; no Kafka, extra capacity, waitlist, manual gate override, offline acceptance or external product alerts enter MVP through this roadmap. Exact issue/forecast provider and deployment choices are made at their owning slice with short ADRs.

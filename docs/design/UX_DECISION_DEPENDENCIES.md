## Fixed cross-screen distinctions

- Event lifecycle and registration availability are different facts. Registration opens on publication unless a future opening is configured; capacity, scheduled/event-based, and Organizer-manual closure are distinct; only capacity-only closure reopens automatically after pre-check-in cancellation. Live transition closes registration even when a later close was configured. Organizer-only Live cancellation blocks registration/check-in and retains existing registrations unchanged.
- No role can cancel a registration after its first accepted check-in; no CANCELLED + INSIDE state is created. Valid check-out or authorized reasoned correction handles occupancy, and explicit issue/revoke handles certificate problems.
- A QR credential is presented by a unique logical scan attempt (`scan_id`). Server validation returns a decision; same-`scan_id` transport retry returns that decision. Only an accepted attendance transition, including an authorized correction event, changes derived occupancy. Failed/new duplicate scans do not.
- Certificate NOT_ELIGIBLE/ELIGIBLE/ISSUED/REVOKED is not email PENDING/SENT/FAILED. An ISSUED certificate can have FAILED delivery; batch progress is a separate operational view.
- Forecasts and alerts advise staff; neither changes gate, capacity, or lifecycle policy autonomously.

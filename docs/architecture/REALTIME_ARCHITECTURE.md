# Phase 2 Real-Time Architecture

**Status:** Slice 7 versioned operations snapshot/socket contract is FINALIZED. Socket.IO over WebSocket is the approved live transport. It carries notification of committed facts, never the authority for gate decisions or occupancy. Kafka is not required. [API snapshot contract](../api/API_CONTRACT.md) and [RBAC](../security/AUTH_RBAC_ARCHITECTURE.md) apply.

Client fetches an authorized event snapshot with `revision` and `as_of`, then opens an authenticated connection and requests an event-scoped subscription. The gateway verifies current session, event assignment and per-topic permission; Gate/Security can join only its assigned gate operational topic, Organizer/Admin the full assigned/owned event view, Volunteer no general stream. Revalidate on reconnect, token/session expiry and assignment change; terminate unauthorized subscriptions. Role-specific serializers strip PII and Gate contacts/OTP/credentials.

Each message has immutable event-message ID, schema version, event/gate scope if applicable, committed occurrence time, source revision/sequence where defined, correlation ID and minimized payload. Candidate types: `scan.decision.accepted/rejected` (gate-scoped minimal result), `attendance.transition.accepted`, `occupancy.updated`, `alert.created/acknowledged/resolved`, `forecast.updated/unavailable`, `certificate.batch.progress`, and operational gate state. A rejected scan never implies attendance/occupancy update. Certificate progress is Organizer/Admin only; participant artifact state comes from own API. No raw QR/token/contact in broadcasts.

Within one event projection stream, increasing revision is the client reconciliation key; cross-topic/global ordering is **not** guaranteed. Clients deduplicate by message ID, ignore older revisions, and detect gaps or heartbeat/age threshold breach. On initial connect, reconnect, gap, schema mismatch, or prolonged disconnect, mark view stale and refetch authoritative snapshot before labeling it live. Display last confirmed time and connection status; do not replay unverified local assumptions. Server can coalesce high-rate updates but must preserve revision/gap detection. Backpressure limits and exact heartbeat/stale durations follow measured workload. Browser fallback is snapshot polling/reload with explicit degraded state, not offline gate acceptance.

Commit attendance/alert/job facts plus reliable publication intent transactionally, then emit after commit. A failed socket send cannot roll back a scan. For one instance, a bounded database publication mechanism is sufficient; multiple instances need shared coordination only if deployment demands it. Test unauthorized joins, assignment revocation, event/gate isolation, duplicate/out-of-order/lost events, reconnect gap, dependency failure and NFR live p95 against an agreed workload.

## Slice 7 finalized operations stream

The authoritative [Slice 7 contract](../api/API_CONTRACT.md#slice-7-finalized-versioned-snapshot-and-socket-contract) fixes the operations GET revision/as_of and `operations.subscribe`, `operations.unsubscribe`, `occupancy.updated` schemas. Revision is the event-scoped committed append-only attendance ledger count, separate from Event.revision. The existing ledger supplies atomic revision and durable publication intent; bounded committed snapshot reads publish only after their transaction completes. No schema migration or competing sequence is needed. Versioned notifications include event identity, stable message identity, schema version, revision, occurrence/read times and correlation, with no participant or occupancy payload. Clients always reconcile authoritative REST, reject old revisions, detect gaps and expose connection/freshness state. Only Organizer/current assigned Admin may subscribe to this event-wide stream. Other candidate topics above remain deferred; the conceptual gate stream is not Slice 7 scope.

Security reasoning: cookie-authenticated WebSockets are vulnerable to cross-site connection attempts, so the gateway checks exact configured Origin beyond CORS and reuses the current account JWT/session verifier. Client event/role selections confer no authority; the REST management lock strategy checks current owner capability or event Admin assignment before acknowledgement and every publication pass. Unauthorized event identity is concealed, old subscriptions are cleared before replacement validation, and generation checks prevent late async deliveries after unsubscribe/disconnect. Publication carries no participant or occupancy data. Committed ledger reads plus REST reconciliation address rollback, loss, duplicate, gap and out-of-order delivery; negative tests cover unauthorized/foreign Origin, role/event isolation, revoked/expired session/assignment/capability and failed transactions.

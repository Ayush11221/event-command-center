# Phase 2 Certificate and Job Architecture

**Status:** workflow contract; no generator, queue, storage or mail provider selected. Source: [Phase 1 certificate rules](../requirements/OPEN_PRODUCT_DECISIONS.md) and [database architecture](DATABASE_ARCHITECTURE.md).

First accepted check-in on non-CANCELLED registration establishes **ELIGIBLE** only. Organizer/Event Admin previews a built-in template/font and explicitly requests single issue or an eligible-database-derived bulk `CertificateBatch`. The command checks event permission and eligibility, persists an idempotent issue intent and batch selection, then bounded work generates a protected unique-ID PDF, records **ISSUED** with artifact provenance, and enqueues independent delivery. Bulk batch → per-registration issue jobs → artifact generation → per-certificate email delivery → batch progress. Only bulk needs a batch; single issue follows the same per-certificate safeguards. No CSV import/custom designer/Gmail OAuth.

Certificate state is NOT_ELIGIBLE → ELIGIBLE → ISSUED → REVOKED. Email delivery is separately PENDING → SENT or FAILED; RETRY is a new controlled attempt from FAILED, not a certificate transition. ISSUED + FAILED is valid. A cancellation after first accepted check-in is prohibited, so issue eligibility cannot be invalidated by later cancellation; if an issued certificate needs invalidation, Organizer/Admin explicitly revokes it. Revocation does not erase historical PDF/attempt evidence and prevents current artifact presentation according to protected access policy.

Idempotency key is scoped to requesting actor, event, action and request fingerprint for batch/single commands. Per-registration unique issue identity prevents duplicate certificate IDs/artifacts; job claims/leases and unique attempt identifiers prevent concurrent workers from generating two logical issues. Store batch eligible/generated/sent/failed counts, status, timestamps and per-item error/retry evidence; derive progress from durable item states rather than unconfirmed messages. Retry transient generation failures with bounded backoff; permanent failures stay visible for authorized recovery. Worker crash resumes from durable state. Email send is asynchronous from a platform sender with optional Organizer Reply-To. Provider outcomes may be uncertain after timeout: reconcile by provider idempotency key/status before resend; if provider cannot guarantee deduplication, document residual risk and use a safe hold/manual investigation rather than blindly sending again. A failed delivery retry does not reissue the certificate. Only Organizer/Admin can retry FAILED; participant sees own status, not batch operations.

Audit explicit request, eligibility rule/version, selected eligible set or reproducible selection snapshot, template/version, issuer, per-certificate generation/issue/revoke, delivery attempt/outcome/retry, batch completion and artifact access. Never log recipient contact or PDF payload unnecessarily. Data/artifact retention, job mechanism, PDF library, storage and mail provider are deferred to the certificate slice. Test partial batches, duplicate commands, concurrent claims, crash after artifact/write/send, recipient isolation, revoked artifact access and ISSUED + FAILED state.

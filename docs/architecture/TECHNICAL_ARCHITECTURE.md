# Phase 2 Technical Architecture

**Status:** implementation blueprint, not implemented. [PRD](../PRD.md) and the [locked decision register](../requirements/OPEN_PRODUCT_DECISIONS.md) govern behavior. This document selects boundaries, not packages to install.

The decision register's Phase 1 list of technical TBDs is historical. Phase 2 selects Socket.IO/WebSocket and tool directions below without changing a locked product decision; all other deferred choices remain explicit.

## System shape and trust flow

Browser (React/TypeScript/Vite) → HTTPS JSON API (Node/TypeScript/Express modular monolith) → PostgreSQL (Prisma data access). The API publishes authorized live updates over Socket.IO/WebSocket from committed facts and calls a bounded Python/FastAPI forecasting service with de-identified time series. A durable database-backed work boundary handles certificate generation/delivery; exact worker, PDF, artifact store, and mail provider are deferred. Docker/Compose and GitHub Actions are development/CI targets when runnable services exist. No Kafka or separate domain microservices are required.

## Frontend ownership (conceptual `frontend/src/`)

Create directories only with real code. `app/` owns router/providers and the Slice 3 application-shell Event + effective Role context: select one authorized context automatically, offer a switcher for multiple authorized contexts (including multiple roles on one Event), and restore a locally remembered selection only after current authorization is confirmed. The selection scopes UI data/navigation/actions but never grants backend authority. `app/` also applies the locally persisted Light/Dark/System presentation preference before rendering; System follows live OS color-scheme changes. Neither preference adds a database field or authorization token. `features/` owns auth, discovery, events, registration, attendance/scanner, command-center, alerts, forecasting, certificates, volunteers; `components/ui`, `common`, `layout` contain reviewed primitives, genuinely shared behavior, and shells. `services/` owns typed API and Socket.IO adapters; `stores/` holds short-lived UI state only; `hooks/`, `lib/`, `types/`, `utils/`, `styles/`, `assets/` appear only for a concrete cross-feature need. Feature code may not import another feature's internals; share a contract or component deliberately.

Routes follow [information architecture](../design/INFORMATION_ARCHITECTURE.md): public discovery/details/registration; own participant credential/certificate; owned/assigned event workspace/setup/gates/command-center/registrations/results/audit; assigned-gate scanner; own volunteer assignment. Exact URLs and auth route split are deferred. The API client owns credentials, correlation IDs, error parsing and retry policy. Domain features own forms and display. Server snapshots are server state; local form drafts, camera controls and dialogs are UI state. No optimistic scan acceptance, cancellation, issue, or volunteer completion. Form checks improve feedback; API validation is authoritative. Authorization-aware rendering hides unavailable actions but never substitutes for server checks. Every surface handles loading, empty, forbidden, error, unknown outcome, stale and reconciling states as applicable. WCAG 2.2 AA, keyboard/focus, non-color statuses, reduced motion, and restrained live announcements are acceptance criteria.

## Backend modular monolith (conceptual `backend/src/`)

`config/` validates configuration; `middleware/` authenticates, correlates, bounds and parses requests; `routes/` mounts versioned endpoints; `websocket/` binds authorized subscriptions to publication; `modules/` owns domains; shared `services/`, `types/`, `utils/` exist only for true cross-domain needs. Modules: auth/guest verification; events/discovery/assignments; registrations/credentials; gates/scans/attendance; occupancy/alerts; forecasting; certificates/batches/delivery; volunteers; audit. A module owns domain policy and repository access, not a separate deployment. Controllers adapt HTTP, validate request shapes and call application services. Services enforce actor/action/event/resource permissions and domain invariants. Transaction scripts/repositories own locking, constraints and atomic facts; controllers do not orchestrate multi-write integrity. A scan transaction persists one decision, accepted transition/projection and critical audit/publication intent together. Downstream event emission happens after commit; consumers deduplicate. Errors map to safe typed API codes, never raw database/provider exceptions. See [database](DATABASE_ARCHITECTURE.md), [API](../api/API_CONTRACT.md), [RBAC](../security/AUTH_RBAC_ARCHITECTURE.md), and [real-time](REALTIME_ARCHITECTURE.md) contracts.

## Non-negotiable cross-boundary invariants

Event state and registration availability differ. One capacity limits REGISTERED registrations, while INSIDE is live occupancy; cap fullness is not a gate block or product alert. A QR credential is not a scan attempt; a scan decision is not an accepted transition. Only accepted transitions, including reasoned corrections, change occupancy. Cancelled events block registration/check-in without rewriting registrations. No role cancels a registration after first accepted check-in. Eligibility does not issue a PDF; certificate and email states are independent. Forecasts and alerts advise humans only.

PRIVATE bearer authority is only for allowlisted PRIVATE Published detail, never management or registration ownership.

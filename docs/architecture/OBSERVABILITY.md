# Phase 2 Observability Architecture

**Status:** instrumentation blueprint, not deployed. Logs/metrics/traces diagnose service behavior; [AuditLog](DATABASE_ARCHITECTURE.md) is distinct protected evidence.

Use Pino structured JSON logging at API/worker boundaries and OpenTelemetry context propagation where useful. Generate/request a correlation ID at ingress, return it in safe errors, and propagate through database publication, Socket.IO, forecast call and certificate work. Capture `scan_id` (not QR token), event/gate IDs where authorized, attendance transition ID, alert condition/record ID, certificate batch/job/issue/delivery attempt IDs, and audit ID as opaque linkage. Never log raw QR, OTP, passwords/session secrets, contact data, PDF payload or unnecessary participant names. Redact request headers/bodies by allowlist; restrict log/audit access and choose retention before real data.

Metrics (aggregated, low-cardinality labels): scan accepted/rejected/technical rate and p95 decision latency; new duplicate versus same-key retry; occupancy/projection lag/reconciliation discrepancy; live publication/connection/reconnect/gap lag; alert active counts by the **three** condition categories/severity; certificate generation throughput, batch progress/queue age and email sent/failed/retry/unknown counts; forecast generation latency, availability and freshness by horizon; auth denial and dependency error rates. Do not label metrics by person, raw token, scan ID or unbounded event ID unless deliberately bounded. Prometheus-compatible collection and Grafana dashboards are candidates where deployment warrants them.

Trace spans cover HTTP ingress/auth/policy, registration or scan transaction, committed publication, live emit, forecast dependency and job generation/delivery; sample safely and avoid sensitive span attributes. Liveness distinguishes process failure from readiness; readiness checks PostgreSQL for authoritative writes and labels optional forecast/live/mail degradation separately. Operational errors use stable code, correlation ID, severity and recoverability; a scan timeout is unknown, not rejected. Alert monitoring here is technical telemetry and does not add a fourth MVP product-alert category. Validate redaction, cross-service correlation, freshness and failure visibility in tests; exact telemetry backend, sampling, retention, paging and SLOs await workload/deployment decisions.

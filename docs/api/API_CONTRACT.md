**Status:** Slice 2 auth/staff foundation and Slice 3 V2–V6 event management, gate readiness, lifecycle, and configuration-only availability are implemented. V7 implements anonymous PUBLIC discovery and event detail. V8 implements Organizer PRIVATE-link issuance and anonymous bearer detail. V9 implements Organizer standalone PRIVATE-link revoke/reissue with atomic replacement and safe replay; other domain rows remain planned later-slice operations. [API_PLAN.md](API_PLAN.md) and [Phase 1 permissions](../requirements/ROLE_PERMISSION_MATRIX.md) remain authoritative. JSON/HTTPS under versioned `/api/v1`; ISO-8601 UTC timestamps and event IANA zone, opaque IDs, cursor-paged lists. OpenAPI will formalize these approved payload schemas during implementation without changing their authority or scope.

## Common command/read semantics

Every protected command authenticates first, authorizes action + event + resource, validates shape/size/state, checks current version when high-impact, then commits facts and audit/publication intent atomically. Never trust browser role, QR contents, client time, or a known ID. Response includes correlation ID and authoritative resource status/revision/time; client timeout means **unknown**, not rejection. Mutation retries use a client idempotency key scoped to actor/action/resource and a request fingerprint where specified; same key/payload returns original outcome, changed payload conflicts. Exact retention windows are deferred. Lists are event-scoped and minimized.

## Final Slice 3 event, discovery, gate and PRIVATE-link contract

The [final approval](../implementation/SLICE_3_FINAL_APPROVAL.md) fixes the technical signature below. **EXISTING** denotes only Slice 2 account/guest proof, session/CSRF, assignment and assigned-gate-scope routes reused here. **PLANNED** denotes an event/discovery/gate operation represented in the older API plan; its exact signature below is **NEW**. These labels record the original contract classification; the status above and IMPLEMENTED V7 labels identify delivered scope. **NEW** operation denotes Organizer-only PRIVATE-link mutation. No Slice 3 product route is EXISTING. All management actions derive owner/assignment from the authenticated account session; query/path IDs never grant authority. `X-CSRF-Token` protects authenticated writes. All write responses carry authoritative event revision and server time; required audit commits with the protected mutation.

### Field, payload and availability schemas

Organizer PATCH allowlist: `name`, `description`, `public_location`, `image_url`, `category`, `tags[]`, `start_at`, `end_at`, `time_zone`, `visibility` (`PUBLIC`/`PRIVATE`), `registration_capacity`, `registration_opens_at`, `registration_closes_at`, `registration_cancellation_cutoff_at`, `registration_manually_closed`, `checkout_enabled`. Assigned Admin PATCH allowlist is **only** `name`, `description`, `public_location`, `image_url`, `category`, `tags[]`; reject any other submitted field rather than ignoring it. Only submitted fields change; null clears optional fields. Validate nonblank name, ordered schedule, valid IANA zone, positive single registration cap, coherent registration times and optional public HTTPS image reference. Organizer policy/configuration changes are Draft/Published-only in Slice 3. No editable certificate eligibility rule, unrestricted Live PATCH, image-upload endpoint, or client-supplied owner/state. An Organizer PRIVATE-to-PUBLIC edit atomically invalidates the active proof so it cannot later revive.

The PRIVATE controlled URL under the configured public origin is `/private#access=<opaque-proof>`. The fragment is captured in browser memory, removed from the visible URL, and presented only as the `PrivateLink` authorization header above; it is not an API query/path parameter or persistent browser storage. The server stores a non-reversible protected verifier, not raw proof. At most one link is active per event. There is **no automatic time-based link expiry in MVP**: Organizer revoke/reissue or leaving PRIVATE Published ends authority, and old proof never resurrects. Account/guest verification is separate for later registration ownership. The API must redact proof/URL from logs, audit and errors, disable private response caching and referrers, and use a configured public origin rather than request Host when constructing URLs.

V8 uses the existing `CONTACT_KEY` as a server-only root for purpose-separated HMAC-SHA-256 verifier and AES-256-GCM replay keys (version 1, labels `eoc.private-link.verifier.v1` and `eoc.private-link.replay.v1`). Keep that root stable: changing it invalidates existing proofs and encrypted replay. Access URLs use the configured `FRONTEND_ORIGIN`, never request Host. Local HTTP remains limited to loopback by the existing application configuration; deployed access requires HTTPS transport. V8 introduced no schema change, active-link TTL, or standalone revoke/reissue endpoint. V9 reuses the persistence foundation for standalone revoke/reissue; reissue results use the same encrypted 24-hour replay window, while secret-free revoke results use ordinary command replay retention.

### Pagination, concurrency, retries and error codes

Both list endpoints use an opaque cursor with optional `cursor`/`limit`, default `limit=20`, maximum `100`, `next_cursor=null` at the end, and no total count. Management order: `created_at DESC,event_id DESC`; PUBLIC order: `published_at DESC,event_id DESC`. Cursor binds sort and query scope; authorization and PUBLIC+Published filter precede pagination. It is not a historical snapshot.

Create Event, create Gate, lifecycle transition, PRIVATE issue/reissue/revoke require `Idempotency-Key` scoped to actor/action/resource plus request fingerprint. Same key/body replays original status/body; changed payload conflicts. Gate, transition and PRIVATE commands also require `If-Match: "<revision>"`; authorized replay is recognized before treating the advanced revision as a new conflict. PATCH requires only `If-Match`, not an idempotency key; on timeout GET/reconcile before a new PATCH. The 24-hour encrypted issuance-response replay window is **not PRIVATE-link expiry**. Active verifier is non-reversible, raw proof is never stored; after replay retention a stale revision blocks accidental second rotation. State change, required audit and one-active constraint commit atomically; audit failure rolls back the mutation. Timeout is an unknown outcome: retry a POST only with the same key/body/precondition, or reconcile from authorized status. Do not return an active URL from management GET.

| --- | --- |
| `400 VALIDATION` | Malformed JSON/query/header, unsupported field/type/range, invalid time/zone/cursor/limit. |
| `401 UNAUTHENTICATED` | Missing/invalid account session on management route; never a PRIVATE proof distinction. |
| `403 FORBIDDEN`, `403 CSRF_INVALID` | Wrong role/action/field or failed authenticated-write CSRF check. |
| `404 EVENT_NOT_FOUND` | Unknown/out-of-scope management ID; unknown/PRIVATE/non-Published PUBLIC detail. |

The common envelope remains `{code,message,correlation_id,details?,retryable?}` with safe field details only. `429` remains generic abuse throttling, not a proof-validity oracle. PRIVATE failure has no public per-cause code. Generic `503` reveals no protected event fact.

### Lifecycle and role boundary

Organizer alone performs Draft→Published, Published→Live, Live→Completed and Draft/Published/Live→Cancelled under [EVENT_LIFECYCLE.md](../requirements/EVENT_LIFECYCLE.md); cancellation requires confirmation and nonblank reason in this Slice 3 command. Publish and Live each independently require at least one persistent authorized Event–Gate association (`UC-02`, `FR-EVT-002`, `FR-EVT-004`). Partial Drafts are savable; no clock-driven event transition or terminal reopening. Event Admin may configure an assigned Draft/Published Gate and edit only its approved fields; Event Admin never transitions, cancels, changes capacity/visibility/schedule/registration policy, or mutates PRIVATE link. Gate/Security, Volunteer, Participant, Guest and anonymous visitors have no management route authority. Anyone with a valid PRIVATE proof can see only the public-allowlisted PRIVATE Published detail. No registration, QR, scan/check-in, occupancy, forecast, alert, certificate or volunteer workflow route is introduced by this Slice 3 contract.

## Error envelope and HTTP categories

Error body: `{ code, message, correlation_id, details?, retryable? }`; field details only for safe validation. The stable Slice 3 catalog is specified above: PRIVATE bearer failures collapse to `404 PRIVATE_UNAVAILABLE`, while protected management without a valid account session is `401 UNAUTHENTICATED`. Later-slice exact codes are finalized with their OpenAPI contracts. Generic categories remain `400` malformed/validation, `403` forbidden, `404` safe not found, `409` duplicate/invalid transition/version/idempotency conflict, `422` distinguishable policy-invalid, `429` throttled, and `503` dependency unavailable. Clients distinguish policy rejection from technical/unknown outcome. No stack traces, raw QR, OTP, account credentials, contact data in gate responses, or internal identifiers that leak private resources.

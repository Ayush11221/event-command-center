## Mandatory high-risk scenario matrix

Registration: same user/event and guest verified email **or** phone duplicate; concurrent last-slot claims; publication/future opening, scheduled/default start, capacity-only auto-reopen versus manual/Live closure; Cancelled event retains rows and denies writes. Cancellation: participant cutoff, staff authority, OTP proof, atomic post-first-check-in denial for **all** roles even after checkout, old QR invalid/new token. Scan: unique client `scan_id` retry returns original; conflicting payload rejected; new duplicate, simultaneous scans, revoked/CANCELLED/wrong-event/Cancelled event, timeout unknown and failed scan never increase occupancy. Attendance: optional checkout, re-entry only after exit, append-only reasoned correction, projection rebuild equals transition fold; registration cap fullness never gate rejection. RBAC: Organizer-only lifecycle/Admin grants/manual close, assigned Admin bounds, assigned-gate minimal identity/read-only alert, volunteer own assignment, participant/guest own resources, restricted audit. Alerts: exactly three categories, INSIDE 90/100 thresholds, persistent-condition dedupe, action authority, no registration-full alert. Certificates: ELIGIBLE without artifact/send, explicit issue, batch partial/crash/concurrent idempotency, unique IDs, ISSUED + FAILED, duplicate-email prevention/provider-unknown recovery, revoked artifact. Forecast: stale/unavailable, advisory non-effect, version/uncertainty/timestamps and chronological baseline evidence.

Each implementation PR should link relevant FR/NFR/UC and negative cases; a compile pass alone is not evidence. No real participant data in fixtures, screenshots or load datasets. Supported device/assistive-tech matrix, workload volumes and later forecast production threshold are deferred.

Slice 3 must additionally prove the approved PRIVATE-link contract against real PostgreSQL semantics: at most one active proof under concurrent issue/reissue; Organizer-only issue/revoke/reissue and Event Admin denial; no time-based link expiry; immediate old-proof denial after atomic replacement/revocation or leaving PRIVATE Published; malformed, wrong-event, revoked, non-PRIVATE, non-Published and unknown attempts all yield the same safe `404 PRIVATE_UNAVAILABLE`; event ID and account/guest OTP alone confer no PRIVATE detail access. Test protected verifier storage, no raw proof/URL in logs or audit, 24-hour encrypted same-key replay versus link validity, CSRF, `If-Match`, idempotency conflict, audit rollback, and distinct PUBLIC versus management serializers. Slice 3 availability tests use only evidenced time/manual policy, not registration count or capacity saturation.
